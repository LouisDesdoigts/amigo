2026-10-30 — Simplified, separate null construction

Fourier: vis_null(optics, vis_model, filt, null_params, spectra=...).
Optical paths are relative to optics. "spectra" selects the explicit source
slope. The visibility basis is fixed; source position is zero and flux unity.
No exposure is involved. vis_jac exposes the response for inspection.

Image: image_null(model, exp, null_params, weighting=None).
Uses exp.to_vec(exp(model)): the existing fitted forward model and valid pixel
support, including detector, ramp and read effects. The visibility path comes
from exp.map_param("vis"). image_jacs exposes both responses for inspection.
No separate normalization, artificial background pedestal or sampling code.
This supersedes the earlier detector_plane/downsample/background API.

Construct K once at an explicitly chosen common reference, then reuse it for
all science/calibrator measurements, predictions and covariance in the same
visibility basis. Filter-specific or otherwise different bases are not
interchangeable. If responses at multiple references must be nulled, combine
responses in common coefficient coordinates BEFORE constructing one kernel;
separately computed kernels cannot be directly subtracted or pooled.

weighting=None is uniform. Explicit weighting must match the forward model's
selected observable rows, including group differences; no PSF is inferred.
Only parameters present in the forward model can be nulled. In particular,
there is no synthetic background parameter. Wholly zero selected responses
are rejected. Existing forward-model gradient stops still apply.

PENDING: numerical validation of derivatives through the full forward model,
finite-difference checks for extended parameters, retained signal and leakage,
and sensitivity to the chosen common optical/image/spectrum reference.
This changes the image response from a separately normalized PSF to the fitted
observable. It does not claim equivalence to archived extended24 results.
The derivative adapter and both matrix kernel algorithms are unchanged.

2026-10-30 — Familiar Trainer interface over the new internals (uncommitted)

Trainer(loss_fn=None, residual_fn=None) supports custom scalar objectives and
residuals. With exposures the callbacks take (model, exposure, args); without
exposures they take (model, args). Scalar callbacks may return (loss, aux).
With neither callback, use the canonical prepared Cholesky objective.

trainer = trainer.normalise(model, parameters, exposures=..., method=...)
Named parameters resolve through exposure.map_param and deduplicate shared paths.
Generic model paths and nested dictionary leaves also work. A mapping of group
names to lists of parameters declares a coupled normalization/optimizer block.
Method is none/diagonal/full, globally or per group. Information source is
residual JTJ or exact scalar Hessian. Custom scalar losses default to Hessian;
residual/Cholesky objectives default to JTJ. Supplied information={group: metric}
bypasses derivatives for that group. Metrics must use OBJECTIVE curvature units:
for canonical MSE this is 2/N times unscaled statistical residual JTJ.

Inspect trainer.groups, methods, sources, reference, reference_args,
reference_exposures, information, transforms and layouts. Canonical data factors
are retained as trainer.prepared and reused for matching exposures. Information
is not recalculated during fitting. Each stage rebases the coordinate origin to
the supplied model, retaining the same transforms and unselected parameters.

trainer.gd uses Armijo, trainer.bfgs and trainer.lm use Optimistix, and
trainer.train accepts ordinary per-group Optax transformations and schedules.
Training batch gradients accumulate before one update per epoch, matching the
previous Trainer. Canonical MSE is weighted by the global sample count, so
changing batch partition does not change the objective. Full blocks cannot be
split across different per-parameter optimizers. No post-update normalization.
LM requires residuals; if both scalar and residual functions are supplied their
values and gradients are checked for consistency at the start and endpoint.
These checks cannot prove equivalence everywhere; callers own that contract.

Results include model, loss, normalized gradient, acceptance/status, aux and
optimizer state. parameter_history stacks the recorded physical states. GD and
Optax record each update; BFGS/LM record only start/endpoint and retain the full
Optimistix solution for diagnostics. Fixed epoch completion without a gradient
tolerance is not certified convergence. Generic result histories are not the
old ParamHistory plotting object; notebooks need explicit plot input updates.

Pipeline defaults, legacy removal, dataset comparison fits, efficient diagonal
information, and two-way Armijo remain separate review items. The generic API
has no default dataset-specific parameter list or scientific acceptance policy.


2026-10-30 — Fixed objective state and explicit preconditioners (uncommitted)

Supersedes the per-call exposures/args and information= API above.
Trainer(loss_fn=None, residual_fn=None, *, exposures=(), args=None) owns the
objective state. The default is full-covariance Cholesky residuals and global
mean-square loss. Generic callbacks use (model, args); exposure callbacks use
(model, exp, args). A custom residual-only objective uses half its squared norm.

normalise(model, parameters, method="diagonal", source=None,
          preconditioner=None, check=False, ...) prepares fixed reference scales.
Source defaults to scalar Hessian for custom scalar objectives, residual JTJ
otherwise. Supplied labelled matrices are explicitly approximate preconditioners;
missing groups are derived from the objective. Canonical MSE curvature includes
2/N; raw statistical JTJ caches require explicit rescaling. Sources are recorded
per group. check=True reports normalized objective curvature at the reference,
without replacing supplied values; it does not prove global equivalence.

Fits reuse stored data and reference transforms, rebasing their origins to the
supplied model. Changed objective state requires normalise again or explicitly
using old information as an approximate preconditioner on a new Trainer.
Batches must partition stored exposures; canonical MSE is partition-invariant.

GD exposes normalized gradient tolerance and Armijo controls. BFGS/LM expose
native rtol/atol plus an additional normalized gradient tolerance. tolerance=None
uses native successful termination (with finite, non-increasing objective).
Optimistix throw=False preserves expected failure results: step caps are
max_steps, accepted=False, with the partial endpoint and native message.
Programming/input errors are not swallowed. Optax epochs_complete is not a
convergence claim. FitResult.criteria records the requested thresholds.

Validation: tiny synthetic correlated-data and custom-objective checks cover
solvers, scaling, cache mismatch reporting, changed-state guards, batching,
Optax histories and step-limit handling. Real AMIGO data fitting remains pending.
Future: investigate bidirectional Armijo step-size adaptation, separately.


2026-10-30 — Two-way Armijo search

GD reuses the last accepted step. If its initial trial fails, shrink to the
first Armijo-valid step; otherwise grow while Armijo holds and loss improves.
Rejected/nonfinite expansion keeps the best accepted trial. A search with no
accepted trial leaves the model unchanged. One budget covers all trials.
API: growth=2, max_search_steps=30 replaces max_backtracks. growth=1 disables
expansion but still reuses steps; it is not the old reset-every-iteration policy.
Histories record accepted rate and search_evaluations. FitResult.evaluations
counts loss_only and value_and_grad calls, including failed searches; Trainer.gd
also counts its endpoint auxiliary evaluation. No objective or scaling change.

Controlled JAX float64 comparisons against committed a263313 used identical
starts, identity coordinates, initial step 1, gradient threshold 1e-5 and budget
5000. All cases converged. Total loss evaluations (including value-and-gradient
